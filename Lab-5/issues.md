# Static Code Analysis Issues Report: Retail Point of Sale System

This document outlines the issues identified by **Bandit**, **Pylint**, and **Flake8** during the initial static code analysis of `pos_system.py`, prioritized by severity (High and Medium severity first), along with the rationale and fix approaches applied.

---

## Issues Summary Table

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---|---|---|
| **Arbitrary Code Execution via `eval()`** (`B307`, `W0123`) | Security (Medium Severity, High Confidence) | 27 | `apply_promo_code` evaluated arbitrary user-supplied string inputs using `eval(code_str)`. This allows remote code execution (e.g. running malicious Python system calls). | Replaced `eval()` with a whitelist dictionary of accepted promo codes (`SAVE10`, `FLAT50`, `HALF`) and a safe regex parser supporting linear math expressions (`total * <factor>`, `total - <val>`) without dynamic execution. |
| **Dangerous Mutable Default Argument** (`W0102`) | Bug / Code Quality | 10 | `process_checkout` defined `receipts=[]` as a default parameter. In Python, mutable default arguments are evaluated once at function definition time, causing state to leak and accumulate between different checkout calls. | Changed the parameter default to `receipts=None` and initialized `receipts = []` inside the function scope if `receipts is None`. |
| **Bare `except:` Catch-All** (`W0702`, `E722`) | Error Handling / Bug Risk | 16 | The cart processing loop used a bare `except:` block. This caught every possible exception, including `KeyboardInterrupt`, `SystemExit`, `TypeError`, and unexpected runtime errors, silently masking bugs. | Removed bare `except:`. Implemented explicit input validation checking if items exist in `PRICE_LIST` and verify that quantities are positive integers. |
| **Silent Exception Swallowing / Try-Except-Pass** (`B110`, `W0718`) | Security & Quality (Low Severity) | 33–34 | `update_stock` caught broad `Exception` and silently executed `pass`. Furthermore, `price_list[item] = price_list[item]` was an ineffective no-op that did not update inventory. | Replaced broad exception catching and silent `pass` with explicit catalogue lookup and structured logging via `LOGGER.warning()` and `LOGGER.info()`. |
| **Resource Leak & Unspecified Encoding** (`R1732`, `W1514`) | Resource Management | 37 | `save_receipt_log` opened a file using `open(file, "a")` without a context manager (`with`) and never called `.close()`, causing potential file descriptor leaks and unbuffered write delays. Also lacked explicit encoding. | Rewrote file I/O to use `with open(filepath, "a", encoding="utf-8") as file_handle:` to guarantee deterministic closing and platform-independent UTF-8 encoding. |
| **Insecure Pseudo-Random Number Generation** (`B311`) | Security (Low Severity) | 21 | Receipt IDs were generated with standard `random.randint()`, which is a pseudo-random generator (Mersenne Twister) prone to collisions and predictable sequences. | Replaced random ID generation with a monotonic, sequential receipt counter (`receipt_counter`) ensuring unique, predictable, and audited receipt identification. |
| **Unused Imports & Dead Variables** (`W0611`, `F401`, `W0612`, `F841`) | Code Cleanliness / Maintainability | 1, 3, 26 | Unused imports `json` and `logging` were included at module root, and local variable `total` in `apply_promo_code` was assigned but never used. | Removed unused imports (keeping configured `logging`), and removed redundant variable assignments. |
| **PEP 8 Style & Naming Conventions** (`C0103`, `E302`, `E305`, `E501`, `C0114`, `C0116`) | Code Style / PEP 8 | Throughout (7, 21, 41, etc.) | Global variables were not named in UPPER_CASE, `printSales` used non-standard camelCase, functions and module lacked docstrings, lines exceeded 79 characters, and blank line spacing around functions was inconsistent. | Encapsulated state in uppercase dictionary `STATE`, renamed `printSales` to `print_sales`, added comprehensive Google/Sphinx style docstrings, formatted to PEP 8 standards (< 80 chars per line, 2 blank lines between top-level functions). |
| **Missing Input & Domain Validation** | Business Logic / Data Integrity | 13–19, 47–49 | The original checkout logic permitted negative item quantities (`("bottle", -4)`) and negative tax rates (`tax_rate=-1`), which reduced bills erroneously without warnings. | Added boundary checks to enforce positive integer quantities and treat negative tax rates as `0.0`, logging warnings for skipped invalid inputs. |
